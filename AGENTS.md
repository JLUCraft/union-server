## Development boundaries

Keep the sibling `federated-skinstation` checkout available for generated contracts. The skin station's active centralization branch is `refactor/central-skinstation-p0`; CI checks out that branch for the shared schemas. The production entry is `federated-server`; `run` starts the configured central game services. Configuration is defined by the Rust types and command parser in `src/`. Production session credentials, forwarding secrets, and spool files stay outside the repository.

Change only the affected subsystem. Use existing dependencies and build directories. Finish each batch before validation; select one validation channel and reuse successful evidence for unchanged inputs. Report skipped checks and device execution limits explicitly.

Centralization keeps the native Minecraft gateway and authenticates players with
the skin station's Yggdrasil `hasJoined`. The skin station owns identity,
authorization, league, events, approvals, and points. Move consumers to those
services and remove federation host dependencies as the migration progresses.

OAuth. Central identity and permissions authorize operations; hosts execute
managed jobs using minecraftd and preserve caller attribution. The historical
`src/ops.rs`, `src/ops_extended.rs`, and `src/rooms.rs` remain reference source,
excluded from the product build; implement the central execution path without
