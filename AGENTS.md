## Development boundaries

Keep sibling `union-core`, `minecraftd`, and `federated-skinstation` checkouts available. The skin station's active centralization branch is `refactor/central-skinstation-p0`; CI checks out that branch for the shared schemas. The production entry is `federated-server`; initialization and signed host registration use its subcommands. Configuration is defined by the Rust types and command parser in `src/`. Production keys and founder authorization stay outside the repository.

Change only the affected subsystem. Use existing dependencies and build directories. Finish each batch before validation; select one validation channel and reuse successful evidence for unchanged inputs. Report skipped checks and device execution limits explicitly.

Centralization keeps the native Minecraft gateway and authenticates players with
the skin station's Yggdrasil `hasJoined`. The skin station owns identity,
authorization, league, events, approvals, and points. Move consumers to those
services and remove federation host dependencies as the migration progresses.
Operations M1–M6 are deferred; do not extend that subsystem.
Skin-station contracts originate in its `shared/contracts/*.schema.json` and are
generated by this crate's `typify` build script.
